# 论文保留、归档与删除规则

目标是维护有用的默认阅读目录，而不是让论文总数持续增长，也不是机械地限制历史文献数量。收录上限是天花板，不是每日配额；没有足够有价值的论文时，可以零收录。

## 1. 三类处理

| 处理 | 适用情况 | 必须保留的信息 |
|---|---|---|
| 保留 | 仍有独立方法、实验、资源或历史参考价值 | 当前评审、局限、核查日期 |
| 归档 | 已被同一工作的正式版本替代；或复查确认不再适合默认阅读目录，但仍值得追溯 | 完整条目、原链接、原评分、归档理由、证据、日期、替代条目（如有） |
| 删除 | 确认重复、误收录、明显超出范围，或官方撤稿/撤回说明已确认核心结论不可用 | 删除记录、证据、原 ID；必要时保留指向替代条目的说明 |

归档表示从默认目录、当前排名和首页精选移出，历史内容仍可检索。删除表示移出当前论文集，不删除 Git 历史或改写过去的日报。资源条目不能因为某篇论文移出就连带删除。

## 2. 不能单独作为删除或归档依据的情况

- 发表时间较早、总分较低、没有开源、引用较少，或作者团队不知名。
- 项目网页或代码链接暂时失效、抓取超时、无法访问 PDF。
- 没有新版本、没有更新代码，或当前轮次没有读到足够材料。
- 名称相近、使用相同基准，或存在性能更高的后续工作。
- 论文数量超过某个整数目标。

上述情况优先更新开放状态、修正链接、降低阅读优先级或记录 `pending_checks`。材料不足时保留既有条目，不把 `defer` 当作删除决定。

## 3. 归档需要满足的证据要求

- **版本替代**：核对作者、项目与版本关系，明确新旧版本的对应关系和内容覆盖；仅“方法相似”不成立。同一 arXiv ID 的修订通常更新原条目，不新增后再归档。
- **阅读价值下降**：至少两次有证据的复查，间隔不少于 30 天；逐项说明原贡献被何种工作覆盖、仍有哪些独有内容，以及为何不再适合默认目录。时间阈值是复查条件，不是自动淘汰条件。
- **经典保护**：`classic: true`、奠基方法、关键数据集/基准/仿真器及仍被使用的代表工作优先保留。保护条目的归档必须明确说明其历史或资源价值为何仍能在归档中得到保留。

撤稿不等于自动删除。先查看官方说明：行政性撤回、版本迁移或存在争议时，应标注状态；只有确认影响核心可信度时才提出删除。

## 4. 每周整理流程

每周一整理一次，优先检查重复/版本关系异常、上轮待核验条目和长期低优先级条目。每轮最多深入复查 30 篇，避免集中清库；没有充分依据时可以不变更。

每项决定记录：原 ID、标题、动作（保留/更新/归档/删除）、具体理由、证据来源与核查结果、复查日期、替代 ID（如有）、经典保护检查。链接之外还需写出支持决定的事实，不能只给 URL。

执行前先生成可审查的变更清单；执行后在当周整理报告列出归档、删除和恢复条目，更新默认目录与数量，运行数据校验、重复检查和链接引用检查，再提交 Git。历史日报保留当时判断，并允许通过当前条目查看最新状态。

归档可恢复：出现新的实验证据、开放资源或重新确认独立价值后，重新评审并恢复；记录原因，不能当成全新论文重复计数。删除记录用于避免误收录再次出现。

## 5. 当前实施边界

本文件定义评审规则，**不表示归档存储、目录过滤或每周自动整理已经实现**。当前自动日报仅在新增筛选时读取本规则，不得擅自改写现有论文的生命周期状态。

现有 `apply_reviews.py` 没有独立归档动作；对已有条目使用 `exclude` 或 `defer` 会移除论文。因此在专用生命周期流程实现并验证前，现有日报评审不得用这两种值处理已收录论文，也不得借助普通日报批量删除。发现问题先记录整理建议，交由单独的维护变更处理。
